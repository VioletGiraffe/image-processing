# Core i5-12600K ("the PC")

The measurement log for this CPU. Sections carry the headings of [resize-performance.md](../resize-performance.md), which
holds each one's rationale.

## Machine

| | |
|---|---|
| CPU | Core i5-12600K: 6 P-cores (Golden Cove), 4 E-cores (Gracemont). P-cores unless a row says otherwise |
| Caches | P-core: 48 KB L1D, 1.25 MB private L2. E-core cluster: 2 MB L2 shared by four cores |
| Toolchain | MSVC 19.51 (toolset v145), Qt 6.11.2; clang-cl where noted |

- Run-to-run noise: 5-8% on the few-ms rows, 1-2% elsewhere.
- P-core and E-core results come from one run: `run_benchmark_rounds.py --pinned P=4 --pinned E=1000`.
  One pinned P-core run and one pinned E-core run at the same time read as each does alone: the display rows' medians
  within 1% on both cores, the 24 MP and 21 MP sources included (2e606ac; nine rounds against five on the P-core, five
  against three on the E-core). Native size, 1.4 ms, read 5% higher on the P-core.
- The notes on E-core throttling, MSVC loop placement and A/B worktrees in the main doc's "Reading the numbers" come from
  this machine.

## Column strips (b9fea7e)

- L2 share per logical processor 512 KB (the E-core cluster: 2 MB, four cores), ring budget 256 KB.
- A process-fault-counter probe: one fault per page with and without strips, but about 1.1-1.2 us each when strips first
  write the pages out of address order, against 0.45 us in order.
- With a reused destination strips cost the upscales -4% to +6%.
